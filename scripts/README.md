# Thumbnail capture

Produces a hub card's `.webp` from the running game.

```
npm run thumbnail                    # every game that has a pose hook
npm run thumbnail -- tube-runner     # just one
```

It starts a dev server, opens the game with `?qa=1`, runs that game's pose
hook, draws the canvas into the card's box, and writes
`src/assets/images/<game>.webp`. Point `QA_URL` at a running server to skip the
spawn.

Afterwards, `npm run qa:units` checks the result: `src/thumbnails_test.ts`
asserts every file is the size `src/App.tsx` declares, which is the same number
this tool captures at — both read it through `qa/thumbnails.mjs`, so the tool
and the check cannot disagree about what correct means.

## Adding a game

Put a `thumbnail.mjs` beside its `index.html`:

```js
export async function pose(page) {
  await page.evaluate(async () => {
    const g = window.__game
    // drive the game to a frame worth photographing
  })
}
```

A game is a directory with **both** an `index.html` and a `thumbnail.mjs`.
Both halves matter: matching on `thumbnail.mjs` alone also matches `scripts/`,
because this tool *is* a `scripts/thumbnail.mjs` — which it did, once, and
then spent thirty seconds waiting for a canvas on the hub's SPA fallback.

The pose hook is the part that cannot be generic. A title screen is rarely the
best card: Tower Stacker's wants a tower part-built with visible ledges and the
next slab still sliding, and Tube Runner's wants rings receding with the runner
mid-stride. Both drive `window.__game`, which `?qa=1` publishes through
`shared/devtools.ts`.

## The treatment

How the canvas becomes a picture — scale, crop, filtering — is one callback in
`scripts/thumbnail.mjs`, and deliberately the only place that decides anything
about how a thumbnail looks.

**#123 has not settled what that treatment should be.** When it does, it
replaces the body of that callback and every card is regenerated by re-running
the tool. That is most of the point of having a tool at all.

Today it fills the card's box, integer-scaled and unsmoothed when the source is
small enough to be pixel art, so a 160x144 game keeps hard 4x4 pixels instead
of a blurred upscale.

## Notes

- The treatment has to be written inline in the `page.evaluate` callback.
  Playwright serialises that callback, so it cannot call anything from the
  module's scope — and the obvious workaround, passing the source and `eval`ing
  it in the page, is blocked by the games' own CSP, which is `script-src 'self'`
  plus a hash and no `unsafe-eval`.
- A capture that produced page errors is reported as a failure rather than
  written. A picture of a broken game is worse than no picture.
- Browser discovery and dev-server spawning come from `qa/harness.mjs`, shared
  with the touch suites. Set `QA_BROWSER` if the Chromium is somewhere unusual.
